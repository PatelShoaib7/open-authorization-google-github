# Phase 1 Security Audit & Legacy Remediation Report

## Executive Summary

A full security audit of the legacy 3-year-old authentication repository (`index.js`, `db.js`, `Configs/google-oauth.js`, `Configs/GutHub-Oauth.js`, `Models/User.js`) uncovered **9 critical/high-severity vulnerabilities** ranging from global cross-user session hijacking and password-hash leakage inside symmetric JWTs to missing CSRF `state` parameters and lack of OAuth 2.1 client validation.

All legacy JavaScript files have been retired and replaced by a strict TypeScript (`strict: true`), layered (`Controller -> Service -> Repository -> Model`) **Centralized Identity Provider (IdP) & Single Sign-On (SSO) Microservice**.

---

## Detailed Findings in Legacy Codebase

| ID | Severity | Legacy Location | Vulnerability / Anti-Pattern | Modern Remediation |
| :--- | :--- | :--- | :--- | :--- |
| **SEC-01** | **CRITICAL** | `index.js:15-16, 28, 41, 81-83` | **Global Mutable Session State & Cross-User Hijacking:** `let Google_Token; let GitHub_Token;` were module-level globals. Once *any* user logged in via Google or GitHub, *every* unauthenticated caller hitting `GET /home` received that user's session and raw upstream GitHub OAuth access token. `Google_Token` was also hardcoded to a static string (`"hb#^0dh488..."`). | Eliminated all global state. Implemented isolated per-user, per-client sessions backed by Redis (`sso:session:*` and `rt:family:*`) and cryptographically signed per-request `RS256` JWTs. Upstream provider tokens are never persisted or exposed to clients. |
| **SEC-02** | **CRITICAL** | `index.js:70` | **Symmetric `HS256` Signing + Password Hash Leaked in JWT Payload:** `jwt.sign({ user }, secret_key, { expiresIn: '24 hr' })` serialized the entire Mongoose `user` document—including the Argon2 password hash—into base64-readable JWT claims, signed with a shared symmetric `HS256` secret valid for 24 hours. | Upgraded to **asymmetric `RS256` (2048-bit RSA)** with `15m` TTL, minimal standard claims (`sub`, `iss`, `aud`, `jti`, `scope`, `roles`), RFC 7638 `kid` thumbprints, and public key discovery via `/.well-known/jwks.json`. `passwordHash` has `select: false` at the Mongoose schema layer. |
| **SEC-03** | **HIGH** | `index.js`, `Configs/*` | **No OAuth 2.1 PKCE, Client Registry, or Redirect Validation:** No `/oauth/authorize` or `/oauth/token` server capabilities existed; implicit/ad-hoc redirects had no registered client whitelist or PKCE verification. | Implemented full **OAuth 2.1 Authorization Code + PKCE (`S256`)** flow. Explicitly blocks deprecated Implicit (`response_type=token`), ROPC (`grant_type=password`), and `plain` PKCE downgrades. Strictly validates `client_id` and exact `redirect_uri` against MongoDB `OAuthClient` records *before* any redirect to eliminate Open Redirects. |
| **SEC-04** | **HIGH** | `index.js:70` | **Long-Lived Unrevocable Tokens & No Refresh Rotation:** 24-hour bearer tokens returned in JSON body with zero revocation or theft detection. | Implemented `15m` Access Tokens paired with `7–30d` opaque Refresh Tokens stored in `HttpOnly`, `Secure`, `SameSite` cookies. Atomic Lua-scripted **Refresh Token Family Rotation & Reuse Detection** in Redis immediately revokes the entire session family if a rotated token is replayed. |
| **SEC-05** | **HIGH** | `Configs/GutHub-Oauth.js:8-34`, `Configs/google-oauth.js:6-27` | **Missing OAuth `state` CSRF & Unverified Email Account Takeover:** Upstream Google/GitHub callbacks did not generate or verify `state` parameters (vulnerable to Login CSRF), logged raw access tokens via `console.log`, hardcoded `https://oauthg.onrender.com/auth/google/callback`, failed when GitHub email was private, and queried `{ id: sub }` on a schema lacking an `id` field. | Replaced Passport & Axios with native OAuth 2.0 + PKCE (`S256`) + single-use Redis `state` (`GETDEL` atomic consumption), GitHub `/user/emails` verified primary email resolution, verified-email requirement prior to account linking, and automatic log redaction. |
| **SEC-06** | **HIGH** | `index.js:49-56`, `Models/User.js` | **Broken Duplicate Check & Unindexed User Schema:** `findOne({ $and: [{ username }, { hashPassword }] })` queried a non-existent `hashPassword` field using a freshly salted Argon2 hash (always returning `null`), called `user.save()` without `await`, and lacked unique indexes on `email` and `username`. | Enforced MongoDB unique indexes on `email`, `username`, and sparse unique indexes on `providers.googleId` / `providers.githubId`, Zod input schemas, and timing-safe dummy Argon2id verification on login to prevent user enumeration. |
| **SEC-07** | **MEDIUM** | `index.js:11` | **Wildcard CORS (`app.use(cors())`) & Missing Security Headers:** Permitted arbitrary origins with zero rate limiting, payload caps, or clickjacking protection. | Added `Helmet` (`frame-ancestors 'none'` CSP), tiered `express-rate-limit` limiters, `32kb` body limits, and **Dynamic Per-Client CORS** backed by registered `OAuthClient.allowedOrigins` cached in Redis. |
| **SEC-08** | **MEDIUM** | `index.js:78-90` | **Double-Response Process Crash (`ERR_HTTP_HEADERS_SENT`):** `GET /home` lacked `return` statements after `res.send(...)` and lacked `try/catch` around `jwt.verify(...)`, crashing the server on invalid tokens or valid logins. | Wrapped all async controllers in `asyncHandler` and routed errors through a centralized RFC 6749 & REST-aware `globalErrorHandler`. |
